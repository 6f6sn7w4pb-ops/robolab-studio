## 1. 两篇论文在做什么

### 1.1 论文 A：两指夹爪的交互中心建模

**要解决的问题**：模仿学习得到的策略容易记住机器人和场景“长什么样”，换一台机器人或换一个相机位置就失效。

**做法**：

- **夹爪坐标系**：把 RGB-D 图像转换成点云，再变换到以夹爪为原点的坐标系里。原点在两指尖完全闭合时的中点，坐标轴跟着夹爪朝向走。（我们的 `gripper0_grip_site` 定义几乎相同。）
- **交互三元组**：只关注三样东西：夹爪、手里拿着的物体、要去的目标物体。两个物体各取 256 个点。
- **势场**：用夹爪的 8 个关键点（掌根 4 个角、4 个指尖）计算两种“场”：离目标多远（吸引），离其他物体多近（排斥，即碰撞风险）。不需要训练，直接由几何算出。
- **夹爪尺寸参数化**：把夹爪的长、宽、高作为参数，换一种夹爪只要改这几个数。
- **整体流程**：一个视觉语言大模型把指令分解成子任务、找出相关物体；SAM 2.1 负责分割和跟踪；一个约 3000 万参数的小型 Transformer 用流匹配（flow matching）输出动作。动作是 7 维末端位姿增量加夹爪开合，20 Hz。

**交互表示的用法**：作为策略的**输入**，不是辅助训练目标。

**训练数据**：仿真用 RoboTwin 2.0，每个任务 50 条示范，共 25 个任务；真机用遥操作，每个任务 50 条，共 4 个任务。交互信息由同一套流程自动生成。

**主要结果**：

| 实验 | 结果 |
| --- | --- |
| RoboTwin 2.0 的 25 个任务（成功率，干净场景 / 随机场景） | 本方法 66.3% / 46.1%；π₀ 61.4% / 24.4%；最好的对比方法 BagelVLA 85.5% / 28.4%。干净场景不是最好，但随机场景明显领先 |
| 真机，相机换位（偏移 35 cm、转 45°） | 对比方法（DP3、π₀.₅）全部 0/10；本方法在抓放、推、堆叠上分别为 2/10、3/10、2/10，倒水为 0/10 |
| 跨机器人零样本（只在一种双臂机器人上训练，直接用到另外两种机器人） | 多个任务仍有一定成功率，但没有给出对比方法 |
| 消融：去掉势场 | 随机场景成功率从 46.1% 降到 35.1% |
| 消融：去掉点云 | 54.9% / 39.2% |
| 消融：夹爪尺寸填错（默认值和真实尺寸相差约一倍） | 62.8% / 43.6%，只下降一点 |
| 消融：点云的筛选方式 | 原始点云 39.2% / 4.2%，按子任务筛选后 61.0% / 35.1%。作者认为随机场景的提升主要来自“按子任务找到相关物体” |

**局限（未逐字核对）**：依赖单视角和大模型，大模型和分割的错误会累积；换视角要手动重新标定；跨机器人部署要求工作空间相近。

### 1.2 论文 B：DextER

**要解决的问题**：按语言指令生成灵巧手的抓取姿态，例如“抓住把手倒水”“握住盖子打开”。作者认为以往方法直接从观测映射到抓取参数，中间没有物理上的推理。

**做法：先预测接触，再预测动作。**

- **接触的表示**：一组“手的部位 + 物体表面上的三维点”。手的部位（比如拇指指尖、食指第一节）用一个符号表示；三维坐标先按整个数据集的范围归一化，每个坐标轴再分成 256 档，各用一个符号表示。
- **生成顺序**：模型先生成接触符号，再生成动作符号。动作是 6 维手腕位姿加手指关节角，同样离散成 256 档。用概率写就是 p(动作, 接触 | 点云, 指令) = p(接触 | 点云, 指令) × p(动作 | 接触, 点云, 指令)。作者称之为“具身思维链”。
- **模型**：语言模型是 Qwen2.5-0.5B；视觉部分用点云编码器 PartField（它的特征能区分物体的各个部件）。输入只有目标物体的点云和指令，没有相机图像。
- **两个训练技巧**：
  - **接触位置随机丢弃**：训练时以一定概率去掉接触的坐标、只保留是哪个部位。概率取 0.5 效果最好；取 1（完全不给位置）时接近“不做接触推理”。
  - **多种提示语**：在指令前加“先一步步想：哪些部位接触哪里……”等多种说法。
- **接触标签怎么来**：把抓取姿态放进 **MuJoCo**，做一次正运动学，直接从物理引擎读出接触。**和我们获取接触的方法相同。**
- **训练成本**：8 张 A6000 显卡，约 48 小时。

**主要结果**（DexGYS 数据集，测试物体都没见过）：

| 方法 | 成功率 | P-FID（越小越好，衡量是否符合指令意图） |
| --- | ---: | ---: |
| 之前最好的方法 DexGYSNet | 63.31% | 5.60 |
| DextER，去掉接触推理 | 62.37% | 0.30 |
| **DextER 完整版** | **67.14%** | **0.20** |

- **接触推理带来的提升**：成功率 +4.8 个百分点，P-FID 从 0.30 降到 0.20。
- **换更大的语言模型**：Qwen2.5-1.5B 只有 67.55%，几乎没有提升。作者认为收益来自接触推理，而不是模型规模。
- **推理时人为指定接触（未逐字核对）**：指定 1 个到 5 个接触部位，成功率从 10.4% 提高到 21.4%。这组数字来自另一个更难的数据集 Dexonomy。
- **接触预测的质量（未逐字核对）**：预测位置在 1 cm 以内的比例约 0.79。
- **局限（未逐字核对）**：只在仿真中评估；只针对单个静止物体；逐个生成符号，误差会累积，速度也偏慢。

## 2. 和本研究的关系

### 2.1 两篇都支持本研究的核心假设

| 本研究的关键词 | 支持的证据 |
| --- | --- |
| **夹爪中心**（Gripper-Centric） | 论文 A：在夹爪坐标系里表达几何，能提高对相机位置和机器人型号变化的泛化；相机换位时其他方法全部失败 |
| **接触**（Contact） | 论文 B：先预测接触再预测动作，按语言指定部位的抓取更准（+4.8 个百分点），而且收益不来自模型变大 |

这两条可以写进论文的“相关工作”和“研究动机”。

### 2.2 本研究的区别和定位

| | 论文 A | 论文 B | **本研究** |
| --- | --- | --- | --- |
| 几何或接触表达在哪个坐标系 | 夹爪坐标系 | 物体表面（相对整个数据集归一化） | **夹爪坐标系** |
| 怎么用 | 作为策略输入 | 作为中间推理步骤 | **只在训练时作为监督信号** |
| 推理时需要的传感器 | RGB-D + 相机标定 | 物体点云 | **只要两路 RGB** |
| 模型 | 自建小模型（约 3000 万参数） | 自建模型（0.5B 语言模型） | **在预训练的大型 VLA（π₀.₅）上加监督** |
| 控制方式 | 闭环 | 一次性输出抓取姿态 | **闭环** |
| 机械手 | 两指夹爪 | 五指灵巧手 | **两指夹爪** |

**可以在论文里强调的优势**：本方法只在训练时使用接触信息，推理时不需要深度相机、点云或额外的感知模块，和“只用两路 RGB”的真机设定一致；同时能直接利用大型 VLA 的预训练能力。

**也要说清楚的差异**：论文 B 不做闭环控制，用的是灵巧手；论文 A 用了深度信息。它们的成功率不能和本研究的结果直接比较。

## 3. 可以借鉴的改进

按“性价比”排序。“工作量”是在现有 RoboLab Studio 平台上实现的估计。

### 3.1 增加“相机换位”的测试条件（强烈建议）

- **来源**：论文 A 最有说服力的实验。
- **做法**：评估时把外部相机的位置和角度偏移一定量（例如几厘米、几度，分几档），其余不变。平台已有“只改渲染、不改物理”的外观变化，相机换位用同样的方式实现，并且可以用同样的方法验证：规则教师的动作和关节位置必须与原数据完全一致，只有图像不同。
- **能回答的问题**：夹爪坐标系的监督，能不能让模型对相机位置更不敏感？
- **价值**：如果成立，论文多一个独立的结论；这对上真机也直接有用，真实相机不可能和仿真装得一模一样。
- **工作量**：小。

### 3.2 单独评估接触预测的质量（建议）

- **来源**：论文 B 单独报告了接触预测的准确度。
- **做法**：本方法的模型本来就要输出预期接触点，仿真里又有真实接触，可以直接计算：每根手指预测点与真实点的距离、1 cm 以内的比例、预测的接触部位（粗端或细端）是否正确。
- **能回答的问题**：成功率提高，是不是真的因为接触预测得准？两者是否相关？这是审稿或答辩时很可能被问到的问题。
- **工作量**：小。

### 3.3 “告诉模型正确接触”的上限实验（建议）

- **来源**：论文 B 推理时人为指定接触的实验。
- **做法**：把真实的预期接触点作为额外输入提供给模型，训练并评估一个“上限版本”。
- **能回答的问题**：如果模型完全知道手指该碰哪里，成功率最多能提高多少？如果上限都不高，说明瓶颈不在接触信息。
- **工作量**：中等，需要多训练一个模型。可以只在部分数据或较少训练步数上做。

### 3.4 “先预测接触、再输出动作”的方法变体（可选，作为后续改进）

- **来源**：论文 B 的核心做法。对应本研究方案（`PROJECT_REPORT.md` 第 17.4 节）里的“方式 C：作为中间推理步骤”。
- **做法参考**：
  - 把每根手指的预期接触点离散成符号（每个坐标 256 档），在动作之前生成。
  - 照搬“接触位置随机丢弃”技巧：训练时以 50% 的概率去掉坐标、只保留是哪根手指。
- **在 π₀.₅ 上的可行性**：π₀.₅ 的设计里有“先生成高层文字（子任务），再由动作专家输出动作”的结构，理论上可以把接触当作这一层来生成。但 openpi 开源代码是否支持训练这一部分，需要读代码确认。
- **建议顺序**：先做最简单的“附加预测维度”（把接触点拼在动作向量后面一起预测），跑通主实验后，再把这个作为改进版本。
- **工作量**：较大。

### 3.5 用“夹爪关键点到障碍物的距离”做碰撞相关的辅助监督（可选）

- **来源**：论文 A 的势场。去掉势场后，随机场景的成功率明显下降。
- **做法**：对夹爪的几个关键点（两个指尖、掌根四角等），计算它们到最近障碍物表面和到目标表面的距离，作为辅助预测目标。现有训练视图里已经有夹爪中心到最近障碍物的距离（`labels/nearest_obstacle`），每帧的完整仿真状态也都保存了，扩展到多个关键点不需要重新采集。
- **能回答的问题**：直接针对研究问题里的“减少碰撞”。
- **与 Book1.xlsx 方案的关系**：比方案里的“两级查询区域占据网格”简单，可以作为第一版的碰撞监督。
- **工作量**：中等。

## 4. 不建议照搬的

| 内容 | 原因 |
| --- | --- |
| 用深度或点云作为模型输入 | 本研究设定为只用 RGB。改用深度就变成另一个问题，也会失去 2.2 节所说的优势 |
| 论文 A 的整套“大模型分解任务 + 分割跟踪”流程 | 太重；它自己的消融显示，主要收益来自任务分解，和“按部位抓取”关系不大 |
| 直接比较成功率数字 | 论文 B 不做闭环、用灵巧手；论文 A 的任务和数据不同 |
| 论文 B 的离散化动作 | π₀.₅ 用流匹配输出连续动作，不需要改成离散符号；只有 3.4 节的接触部分才需要离散化 |

## 7. 补充：真实环境中的安装误差，模型还能用吗（2026-11-22 讨论）

问题：真实环境里，相机的角度、距离、高度，以及桌子的摆放，都会和仿真有一定误差。模型还能工作吗？会不会自己微调？

### 7.1 结论

- **不会自己微调。** 训练结束后参数就固定了，真机上只是“看图 → 输出动作”，不会边用边学。
- **闭环能纠正“动作走偏”，纠正不了“看错”。** 模型每执行 5 步就重新看一次画面，夹爪走偏一点能修正；但如果相机位置和训练时不同，画面里物体的位置、大小、角度会有系统性偏差，模型可能一直朝错误的地方走。
- **模型不知道相机挪了。** π₀.₅ 只接收图像和指令，不接收相机内外参，只能靠训练时见过的画面多样性去适应。
- **能不能扛住，取决于训练时有没有“见过”这种程度的误差。** 做好“真机尽量对准仿真”和“训练时故意让相机、桌子的位置随机变化”两件事，几厘米、几度以内的误差一般能扛住。具体能容忍多大，现在没有数字，需要用实验测出来。

### 7.2 各种误差的影响（定性判断）

| 误差来源 | 影响 | 原因 |
| --- | --- | --- |
| 腕部相机支架的装配误差 | 较小 | 支架按仿真尺寸 3D 打印，误差通常是毫米级、一两度；相机跟着夹爪动，看到的始终是“物体相对夹爪在哪”，和夹爪坐标系的思路一致 |
| 外部相机的位置和角度 | 较大 | 三脚架摆放可能差几厘米、几度，物体在画面里的位置会整体偏移 |
| 相机内参（视场角、畸变） | 中等 | 规格书说法不一（90°×65° 和 86°×57°），要以实际读出的数值为准 |
| 桌子水平摆放 | 较小 | 动作是末端的增量，不是绝对坐标。只要物体还在训练时的摆放范围内（底座前 30–70 cm、左右 ±40 cm），就是见过的情况 |
| 桌子高度 | 中等 | 训练时桌面高度固定为 74 cm；差得多了可能抓空或撞到桌面。但它能用尺子量到毫米级，直接填进仿真即可 |
| 仿真和真机的控制器不同 | **可能最大** | 见 7.4 节第 4 条 |

### 7.3 怎样让模型扛得住

1. **先把误差压小：真机对准仿真。** 相机位置在仿真里定好，真机支架照做；装好后标定：外部相机用棋盘格或 AprilTag 测出实际位姿，腕部相机做手眼标定，读出两台 D455 的真实内参。偏差较大时，要么把真机调回去，要么把实测值填回仿真重新生成数据（`PROJECT_REPORT.md` 第 19.2 节）。
2. **再让模型见过误差：训练数据随机化。** 生成每条数据时，在一定范围内随机改变：外部相机的位置和角度（例如 ±2 cm、±3°）、腕部相机的装配偏差（例如 ±3 mm、±1°）、相机焦距（例如 ±3%），再加上已有的光照、背景、颜色变化。这些数值只是举例，**范围要按标定后实测的误差来定，并稍微大一点把真实误差包住**；范围太大会让任务变难，需要更多数据。桌面高度能量准，只需很小的随机范围，覆盖桌面不平和物体放置的微小差别。
3. **用实验测出能容忍多大误差。** 评估框架加一个“相机扰动”选项（与第 3.1 节的“相机换位”是同一件事），按几档误差各跑一遍，例如 0、1、2、4 cm 和 0、2、5°，画出“误差越大、成功率怎么下降”的曲线。
4. **真机上仍然不行：少量真机示范微调。** 用遥操作在真机上录几十条示范再微调。这有效，但就不再是“零真机数据”，论文里要单独报告。

### 7.4 补充与修正

1. **官方配置下，π₀.₅ 不使用机器人状态。** `pi05_libero` 的配置是 `discrete_state_input=False`。π₀.₅ 的结构里，状态只有在这个选项打开时，才会以文字符号的形式输入模型。所以我们导出的 8 维状态，用官方配置训练时没有用上。写 LoRA 配置时要专门决定：
   - 打开：模型能看到夹爪当前的位置和开合，可能有帮助；
   - 不打开：与官方设置一致，便于比较。

   这一点请在 openpi 的模型代码里确认。
2. **openpi 训练时可能已经自带图像增强。** 据了解，openpi 训练时会对图像做随机裁剪、外部相机图像小角度旋转、颜色抖动，这本身就让模型对相机的小幅偏移有一定容忍。具体做了哪些、幅度多大，需要在 openpi 代码里确认（大概在 `src/openpi/models/model.py` 的图像预处理部分），再据此决定仿真里的相机随机化做多大，避免重复或不足。
3. **可以加一个训练技巧：偶尔“遮住”外部相机。** 训练时以一定概率把外部相机图像换成黑图或加大扰动，逼模型更多依靠腕部相机。腕部相机跟着夹爪走，几乎不受外部相机摆放误差的影响，也贴合“夹爪中心”的思路。可以作为一个消融实验。
4. **控制器差异要在真机阶段第一步就单独测。** 仿真里一个归一化动作精确对应 5 cm 的位移，真机上要保证同一个动作对应同样的位移，响应速度也接近。另外，推理每次约 88 ms，每次执行 5 步、控制频率 20 Hz，真机上要确认推理和控制能跟上节拍。这些比相机误差更该先排查。
5. **关于零样本评估的例子**：`pi05_libero` 在我们的场景里把机械臂伸向障碍物，主要原因是任务、物体、指令全都没见过，不是相机误差。它可以说明“模型不会自动调整”，但不能作为相机误差影响大小的证据。

### 7.5 和课题本身的关系

本方法让模型学习“手指会在夹爪坐标系的哪里碰到物体”，这个目标和外部相机摆在哪里无关。所以有一个合理的猜想：**加了接触监督的模型（M2），对外部相机的位置误差可能比基线（M1）更不敏感。** 在 7.3 节第 3 条的相机扰动评估里同时比较 M1 和 M2，就能检验这个猜想；无论结果如何，都是有意义的结论。

另一条路是参考论文 G³VLA 的做法：把相机参数也输入模型（射线嵌入），让它“知道”相机在哪；真机上只要标定准确，模型就能考虑相机的变化。这已列为主实验之后的扩展。
