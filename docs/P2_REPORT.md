# P2 第一批：可重复规则抓取与轨迹记录

日期：2026-11-02，Europe/London。按用户“逐步开发”的要求，本轮从已验证的 P0/P1 继续推进。复用已有 Panda 规则抓取，不重建环境、不加载 VLA 权重。

## 在平台中使用

关闭旧窗口，按原方式启动 RoboLab Studio。加载默认 LIBERO-Object 汤罐任务，右侧选择“策略 / 自检”，点击 **P2 规则抓取与记录（非 VLA）**。英文为 **P2 grasp + record (scripted)**。

机器人执行稳定物体、接近、闭爪、提升、搬运、放下和退出。界面显示阶段及进度，并单独显示双指接触、持续提升、官方任务结果和记录目录。✓ 表示该项已满足；— 表示尚未满足或没有最终判定。只有运行结束且全部条件通过，记录才会显示通过。

顶部“暂停”可冻结动作和物理时间；暂停后“单步 +20ms”会推进一次并增加一条轨迹。“启动物理仿真”可继续。右侧“结束策略”取消本次执行并保存 cancelled 记录。停止/重置/关闭窗口也会结束正在执行的记录；取消不报告为成功。

“复制抓取记录路径”提供 Windows 可用的 WSL UNC 路径；“打开抓取记录”交给文件管理器。该功能继续支持中英文切换，语言变化不重启执行。

当前仅支持原有默认汤罐任务和未添加额外刚体的 LIBERO 场景。不会偷偷恢复或覆盖用户当前编辑布局；要重复官方初态，应重新加载默认任务。重置恢复最近编辑基准，不一定恢复最初官方布局。

## 判定依据

规则轨迹继续使用仿真真值、IK 和既有 Panda 关节 PD 控制。它不是 VLA、不理解新指令，也不是未见物体泛化结果。记录动作是 7 关节目标（rad）和夹爪打开比例，与策略接口的 7 维 OSC 动作不同。

| 判定 | 明确定义 |
| --- | --- |
| 双指接触 | 关闭/提升阶段，两个手指各有目标物体接触，连续采样跨度至少 0.20 秒；不把手掌或其他物体接触算进去 |
| 持续提升 | 稳定后的目标高度为基准，提升至少 0.10 米，且双指接触连续观测至少 0.50 秒 |
| 官方任务完成 | 同步最终物理状态到既有 LIBERO，调用官方任务判定 |
| 本次通过 | 执行正常结束，以上三项全部满足 |

接触判定只接受手指与目标对应的 MuJoCo 接触，排除正距离的接近记录。时间跨度按连续有效观测的首尾时刻计算，控制采样间隔为 0.02 秒。没有接触、提升不足、接触中断或被取消都不能误报完整通过。

这是 P2 所需的物理证据检查，仅记录两个接触布尔值。完整的指尖接触点、法向、力和夹爪坐标转换仍留在 P3。

## 保存内容

正常平台输出为 `outputs/p2_grasp/<UTC时间_标识>/`，可用 `ROBOLAB_P2_OUTPUT_DIR` 覆盖位置：

- `metadata.json`：任务、seed/初态索引、Python/依赖版本、代码 SHA256、LIBERO commit、控制参数、几何映射、判定阈值、各项结果、样本数及轨迹哈希。
- `trajectory.jsonl`：每条记录包含仿真时间、阶段、实际关节位置/速度、关节目标、限速后的伺服目标、夹爪状态、原生执行器控制量、末端位姿、目标位姿和两个手指的接触状态。

位置使用世界坐标和米，四元数为 wxyz，关节角单位 rad。Panda 手臂原生控制量为力矩，手指位置伺服为米，不能把所有执行器数值解释为同一单位。

记录不会修改物体位姿。JSONL 不是全场景求解器快照，也没有每帧双 RGB，因此本轮不宣称已经实现完整 episode 回放或训练数据集。

## 实际测试

| 检查 | 结果 |
| --- | --- |
| 固定 seed 0 / 官方初态 0，重复 3 次 | 全部完成接近、夹持、提升和放置；最终 qpos 最大差为 0 |
| 实际提升 | 三次最大提升均约 0.284522 米 |
| 连续接触与提升 | 最大双指接触跨度约 3.92 秒；满足高度与双指条件的连续跨度约 1.82 秒 |
| 轨迹完整性 | 每次 22 秒仿真、1,101 条记录；时间严格递增，JSONL SHA256 校验通过 |
| 控制量 | 关节伺服最大变化率约 0.6 rad/s；原生执行器命令均在模型控制范围内 |
| 物理失败对照 | 只在验证进程中禁用接近 IK，实际未抓住目标；判为 failed，提升标志为 false，不复用成功记录 |
| 判定边界单测 | 4 项通过：无接触、有接触但无提升、接触中断、持续时间与异常时间 |
| 真实桌面操作 | 抓取、暂停、20ms 单步、继续、双语结果、路径复制、取消独立记录通过；关闭后端退出 |
| 旧策略链路 | 原 `test_vla_pipeline.py` 通过：双 RGB → Mock → 官方 OSC → 物理变化，以及规则任务成功 |
| 双语回归 | 7 项本地化测试通过，新增模板占位符与状态翻译保持有效 |
| 结果卡边界 | 用保存的真实状态做轻量界面检查：即使状态字符串为 succeeded，只要完整 P2 标志为 false，仍显示未通过；取消单独显示 |
| 环境保护 | 包版本、6 个受保护文件、LIBERO/OFT Git 状态与上轮快照一致，pip check 通过 |

CLI 的最终重复试验及失败对照共耗时 98.161 秒（包括渲染初始化与证据导出），最终桌面测试耗时 94.369 秒。暂停/单步的 GUI 运行与 CLI 的最终 qpos 最大差也为 0。三次相同初态的通过证明本机可复现，不是多任务、多 seed 或未见物体成功率。

失败对照会在验证元数据中注明 `verification_only_fault_injection=disable_scripted_ik`，避免与正常基线混淆。本次已有失败对照补注了来源说明，未修改原始轨迹或测量值。

原依赖仍有 Gym/robosuite 提示；旧集成测试还会报告 robosuite 读取临时 XML 时的 ResourceWarning，测试正常结束。本轮没有修改第三方库来隐藏这些信息。OFT 原有 protobuf 导入故障不在本轮修复，真实模型仍未验证。

## 本轮变更与后续

新增 `p2_recording.py`、判定单测和 CLI/桌面验收脚本；在既有 `ScriptedPickPlace` 中增加只读证据采样与记录。在引擎中让暂停的规则执行支持真正单步，并在取消/异常时保存结束状态；GUI 增加结果卡与记录路径操作。P1 目录操作整理为共用函数，模型接口和原有仿真环境保持独立。

本轮完成的是 P2 第一批：默认规则抓取闭环的可重复验收和状态轨迹记录。下一批补末端点动与记录浏览/状态回放，再进入完整 P3 接触数据。当前没有任意物体自动抓取、全场景精确回放、正式接触标签、训练或实机控制。
