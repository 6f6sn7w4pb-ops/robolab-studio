### 1.1 桥接服务做的事

模型（openpi，Python 3.11 + JAX）和仿真（Python 3.10 + MuJoCo 2.3.7）环境互不兼容，所以模型单独跑成一个本地 HTTP 服务，仿真每次通过 `HttpPolicy` 发观测、拿动作（RoboLab 桥接协议 v1，见 [VLA_INTEGRATION.md](VLA_INTEGRATION.md)）。

| 环节 | 做法 | 依据 |
| --- | --- | --- |
| 图像 | 两路 224×224 JPEG 解码成 uint8，再**水平翻转** `image[:, ::-1]` | openpi 的 LIBERO 示例把原始 robosuite 帧旋转 180°；我们的“规范图像”= 原始帧上下翻转，所以 180° 旋转 = 规范图像左右翻转。已对照 `examples/libero/main.py`、[P4_DATASET_FORMAT.md](P4_DATASET_FORMAT.md) 第 4 节、`robolab/openvla_service.py`，并有单元测试 |
| 状态 | 8 维 proprio 原样传入 `observation/state` | 与 openpi LIBERO 示例定义相同。**`pi05_libero` 实际不读状态**：π₀.₅ 不加状态 token，且配置为 `discrete_state_input=False` |
| 指令 | `prompt` = 观测里的英文指令 | |
| 输出 | `policy.infer(...)["actions"]`，(10, 7) | `pi05_libero` 一次输出 10 步，评估每次执行前 5 步（`--execute-steps 5`），与官方 `replan_steps=5` 一致 |
| 裁剪 | 超出 [−1, 1] **不到 0.05** 的裁剪到 ±1，并在响应里返回 `clipped_values`、`max_excess`；**超出 0.05 及以上**返回错误、不裁剪 | 评估框架对 >1.0 的动作严格判为策略错误，而模型夹爪一维常有 1.00x |
| 并发 | 推理加锁串行 | 4 个评估进程共用显卡上的一个模型 |
| 安全 | 只接受本地检查点目录，从不下载；设 `HF_HUB_OFFLINE=1` | |

## 3. 接口检查

除数字外，用全部 240 条的 trace（每 tick 的状态、动作、物体和障碍物位姿）检查接口，并看了代表性条目的关键帧。

| 问题 | 方法 | 结果 | 结论 |
| --- | --- | --- | --- |
| 机械臂是否朝物体移动 | 末端到物体**初始**水平位置的距离 | 起始约 23.7 cm → 前 120 tick 内最近距离中位数 **1.2 cm**；84% 到过 5 cm 以内 | 是 |
| 夹爪是否开合 | 夹爪指令符号变化、两指关节开度 | 100% 条目发出过闭合指令；开度约 0.2–8.0 cm（中位数）；每条开合切换中位数 8 次；112 条抬起物体 | 是 |
| 控制方向是否反 | 动作 x/y/z 与下一 tick 末端实际位移的相关系数 | **0.94 / 0.97 / 0.95** | 没反 |
| 图像左右是否反 | 若翻转弄反，机械臂会去物体关于起点的左右镜像位置 | 到镜像位置的最近距离中位数 **20.6 cm**，到真实物体 1.2 cm | 没反 |

局限：

- 各场景物体位置只差 2–3 cm（标准差约 2.5 cm），无法检验厘米级的跟随。末端到达位置随物体位置变化的回归斜率 x 0.43、y 0.11，说明**精细定位弱**，这也和部位正确率接近随机一致。
- 统计“最近时刻”时必须用物体的**初始**位置：模型抬起物体后，物体随夹爪移动，用三维实时距离会选错时刻（分析时踩过这个坑）。
- “真实推理”还没有在官方 LIBERO 任务上复现论文成绩。以上只能间接证明方向正确，不能排除更细的偏差（例如 JPEG 压缩的影响）。在官方 LIBERO-Object 上跑出接近论文的成绩，才是最强的证据。

## 4. 复跑不一致与噪声来源

- 默认复跑 2 条：`box_step-test_instance-000_thick`、`ellipsoid_step-test_unseen-000_thick`。两条的 trace、关键帧都与原来不同（`recheck_identical=false`），但判定结果相同（前者两次成功，后者两次碰到指定部位但没抬起）。
- **噪声来源**：openpi 的 `Policy` 在服务启动时用 `jax.random.key(0)` 建一个随机数种子（`src/openpi/policies/policy.py` 第 65 行），**每处理一次请求就切出一份新的随机数**（第 75 行）作为流匹配的初始噪声。所以一次请求拿到的噪声只取决于它是服务启动后第几个被处理的请求；4 个评估进程并发，**到达顺序每次不同**，服务重启也会把计数归零。
- **能否固定**：可以。这个版本的 `Policy.infer(obs, *, noise=None)` 支持直接传入噪声（第 83–88 行），形状 (10, 32)。可以按“条目 + tick”算出确定的噪声传入，使模型评估也能逐字节复现。是否这样做在第 2 步讨论，这次没有改代码。

## 5. 对论文的意义

- **M0 基准成功率 15.0% [11.0, 20.1]**。
- 模型**不区分部位**（接触时部位正确率 51.8%，粗端 76% vs 细端 27%），并且 **43/240 条把障碍物当成目标**。这两点都是“按语言指定部位抓取”所需要、而通用 VLA 缺乏的能力，正是夹爪坐标系接触监督要改善的地方。
- 这次的场景是**旧布局**（物体在地面、LIBERO 默认相机）。2026-11-20 已决定新数据和新测试全部改用实验室布局，所以在新测试场景上要重跑一次 M0（见 [LAB_MASTER_PLAN.md](LAB_MASTER_PLAN.md)）。本次结果作为前期基准保留。

## 7. 复现命令

先确认没有激活 `~/vla/.venv`（必要时 `deactivate`），并切到 `pi05-bridge` 分支。

终端 A（服务，约 35 s 就绪）：

```bash
cd ~/projects/openpi
env -u VIRTUAL_ENV XLA_PYTHON_CLIENT_PREALLOCATE=false HF_HUB_OFFLINE=1 \
  ~/projects/openpi/.venv/bin/python ~/projects/robolab-studio/scripts/serve_openpi_bridge.py \
  --config pi05_libero --checkpoint ~/.cache/openpi/openpi-assets/checkpoints/pi05_libero --port 8000 \
  --request-log <请求日志.jsonl>
```

终端 B（评估，4 进程约 27 分钟）：

```bash
cd ~/projects/robolab-studio
bash scripts/launch.sh --p5-eval --policy adapter:pi05 --endpoint http://127.0.0.1:8000 --timeout 60 \
  --dataset outputs/p4d_lab --scene-set extended --anti-roll --execute-steps 5 --workers 4 \
  --output-dir outputs/<新目录>
```

停止时**先停评估、后停服务**：对评估主进程发 SIGTERM（或 Ctrl+C），它会等每个进程做完当前这条再退出；如果先停服务，正在跑的条目会被记成策略错误，且 `--resume` 不会重跑它。
