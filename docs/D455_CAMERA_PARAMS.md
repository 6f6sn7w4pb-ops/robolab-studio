# 两台 RealSense D455 的实测参数（2026-11-25）

2026-11-25 在实验室读出了两台 D455 的参数。这些参数是相机出厂时标定好、存在相机里的，用两种工具各读了一遍，结果完全一致（见第 6 节）。项目只用彩色画面（RGB），所以正文只列彩色相机的参数；深度、红外、IMU 的参数在原始文件里（见第 8 节）。

## 1. 先看这里

| --- | --- | ---: | --- |
| **第一台** | 246322302827 | **63.789°** | 腕部 |
| **第二台** | 141322252821 | **65.031°** | 外部 |

- “第一台”“第二台”已经标记在相机机身上。序列号后四位（2827、2821）很像，靠序列号认相机时看前四位（2463、1413）。
- 两台型号相同，但出厂标定不一样：第二台的视角宽一点，焦距短 2.4%。**仿真里每台相机要用它自己的 fovy。**
- **第一台装腕部，第二台做外部相机**（用户 2026-11-25 定；第二台就是 USB 口偏松的那台，见第 7 节）。[calibration/d455_cameras.json](calibration/d455_cameras.json) 里的 `role` 已经填好；[robolab/lab_scene.py](../robolab/lab_scene.py) 的 `D455_UNITS` 按这个分配给两个仿真相机各自的 fovy。腕部支架的位置研究用 [scripts/study_wrist_camera.py](../scripts/study_wrist_camera.py)，支架尺寸说明待写。

## 2. 这些参数是什么意思

相机把三维空间里的点投影到画面上，常用“小孔成像”模型来描述。下面几个参数决定一个点落在画面的哪个像素上：

- **fx、fy（焦距，单位是像素）**：数值越大，视角越窄，物体在画面里越大。fx 管横向，fy 管纵向。
- **ppx、ppy（主点）**：镜头光轴穿过画面的位置。理想情况下在画面正中；1280×800 的正中是 (639.5, 399.5)。
- **畸变系数**：真实镜头不是理想的小孔，越靠近画面边缘，图像越有一点弯。D455 用的畸变模型叫 Inverse Brown–Conrady，有 5 个系数（k1、k2、p1、p2、k3）。
- **视场角**：画面左右（水平）和上下（垂直）各能看到多少度。
- **fovy**：MuJoCo 的仿真相机只有一个视角参数 fovy，就是垂直视场角，按 fovy = 2·atan(画面高度 ÷ 2 ÷ fy) 计算。它默认像素是正方形、主点在画面正中、没有畸变。

## 3. 彩色 1280×800（仿真用的就是这个分辨率）

| 项目 | 第一台 | 第二台 |
| --- | ---: | ---: |
| 序列号 | 246322302827 | 141322252821 |
| 仿真用 fovy | **63.789°** | **65.031°** |
| 视场角（水平 × 垂直） | 89.67° × 63.79° | 91.06° × 65.01° |
| fx | 643.696 | 628.235 |
| fy | 642.766 | 627.500 |
| ppx | 645.196 | 638.624 |
| ppy | 396.680 | 413.391 |
| 主点偏离画面中心（像素） | (+5.7, −2.8) | (−0.9, +13.9) |
| fx/fy − 1 | +0.145% | +0.117% |
| 畸变系数 k1, k2, p1, p2, k3 | −0.05610, 0.06474, −0.00032, 0.00037, −0.02085 | −0.05745, 0.07317, −0.00041, 0.00042, −0.02323 |
| 畸变造成的最大偏移 | 8.9 像素 | 7.2 像素 |
| 固件 / USB | 5.13.0.50 / 3.2 | 5.13.0.50 / 3.2 |

视场角和主点偏移按 librealsense 的约定计算：(0, 0) 是左上角那个像素的中心。“畸变造成的最大偏移”是在整幅 1280×800 画面里，畸变让一个点移动的最大距离。

## 4. 这些数字对仿真意味着什么

1. **和之前的假设基本一致。** 之前的相机位置研究（[LAB_CAMERA_STUDY.md](LAB_CAMERA_STUDY.md)）按规格页上的“90°×65°”来算。第二台几乎正好是 91°×65°，第一台窄约 1.2°，所以研究结论不用改。另一种说法“86°×57°”不是 1280×800 彩色画面的数值：57–60° 对应的是 16:9 的分辨率（见第 5 节的 1280×720）。
2. **两台焦距差 2.4%。** 如果两台仿真相机共用一个 fovy，物体大小会差 2.4%；在策略实际看到的 224×140 画面里，上下边缘约差 1.7 像素、左右边缘约 2.7 像素、四角约 3.2 像素（画面中心不差，越往边上差得越多）。所以每台用自己的 fovy。
3. **主点偏移。** MuJoCo 的主点只能在画面正中。第一台偏 (+5.7, −2.8) 像素，第二台往下偏 13.9 像素；缩到 224×140 以后，分别约 1 像素和 2.4 像素。目前可以先不管。以后真机和仿真叠图要更准的话，可以把仿真图多渲染一圈，再按偏移量裁剪。
4. **畸变很小。** 缩到 224 宽以后，两台的最大偏移都不到 1.6 像素，仿真里用理想的小孔相机就够了。
5. **像素可以当正方形。** fx 和 fy 只差 0.1%–0.15%，符合 MuJoCo 的假设。

## 5. 其他分辨率的 fovy

| 分辨率 | 第一台 fovy | 第二台 fovy | RGB8 可用帧率 |
| --- | ---: | ---: | --- |
| 1280×800 | 63.79° | 65.03° | 5, 10, 15, 30 |
| 1280×720 | 58.50° | 59.69° | 5, 10, 15, 30 |
| 848×480 | 58.81° | 60.00° | 5, 15, 30, 60 |
| 640×480 | 63.79° | 65.03° | 5, 15, 30, 60 |
| 640×360 | 58.50° | 59.69° | 5, 15, 30, 60, 90 |
| 480×270 | 58.50° | 59.69° | 5, 15, 30, 60, 90 |
| 424×240 | 58.81° | 60.00° | 5, 15, 30, 60, 90 |

彩色传感器原本就是 1280×800（16:10）：

- **16:9 的分辨率**（1280×720、848×480 等）是在 1280×800 的基础上裁掉上下两边（有的还再缩放）得到的，所以垂直视场角更小。
- **640×480** 是先缩放、再裁掉左右两边，所以垂直视场角和 1280×800 一样。

每个分辨率完整的 fx、fy、ppx、ppy 都在 [calibration/d455_cameras.json](calibration/d455_cameras.json) 里。

## 6. 怎么读的、怎么核对的

- **时间和接法**：2026-11-25，在实验室，相机用 USB 3 接到笔记本，在 Windows 11 上读。WSL 默认看不到 USB 相机，所以没有在 WSL 里读。
- **工具一**：本仓库的 [scripts/read_realsense_params.py](../scripts/read_realsense_params.py)。它只读，不改相机设置，也不碰固件；用的是 RealSense 官方 Python 库 pyrealsense2 2.59.2。
- **工具二**：RealSense 官方命令行工具 `rs-enumerate-devices -c`（librealsense v2.59.2）。下载后核对过 SHA-256。
- **核对结果**：每台相机都对比了两种工具读出的 38 组内参（彩色、深度、红外的所有分辨率）和 6 组外参，全部一致，最大差别是 6×10⁻¹³，只是打印时的四舍五入。
- **固件**：两台都是 5.13.0.50，没有升级。

在另一台 Windows 电脑上重新读的方法如下。

先在 PowerShell 里建一个独立的 Python 环境（只需要做一次）：

```powershell
py -m venv $HOME\realsense-tools\venv
& $HOME\realsense-tools\venv\Scripts\python.exe -m pip install pyrealsense2==2.59.2.11152
```

然后在 WSL 里、本仓库目录下运行。命令里的 `<Windows用户名>` 换成实际的用户名：

```bash
/mnt/c/Users/<Windows用户名>/realsense-tools/venv/Scripts/python.exe scripts/read_realsense_params.py --out outputs/realsense_params
```

官方工具从 [v2.59.2 发布页](https://github.com/realsenseai/librealsense/releases/tag/v2.59.2) 下载 `rs-enumerate-devices.exe`，不用安装。它的 SHA-256 是 `ac4604caec11a8317231b019c41654e782afb89057320db8d6a2a6e75463b48b`。下载后运行：

```powershell
.\rs-enumerate-devices.exe -c
```

## 7. 注意事项

- **第二台的 USB 接口可能有点松。** 读参数那天，它前几次插上时电脑完全没识别到，同一根线、同一个口接第一台却正常，重新插好以后第二台才被识别。正式采数据时要检查接口插牢，最好把线固定住。
- **不要升级相机固件。** 读参数用不着升级。
- **读参数时拍的照片没有上传。** 每台拍了一张，里面拍到了人，只留在笔记本的 `outputs/` 里。
- **外参要另外确定。** 外参是相机相对机械臂的位置和朝向，不存在相机里，要按支架设计来定，或者通过标定得到。
